# 🥐 Бот пекарни «Тёплый хлеб»

Telegram-бот для приёма заказов в пекарне. Учебный проект для портфолио.

**Стек:** Python 3.11+, [aiogram 3](https://docs.aiogram.dev/), SQLite ([aiosqlite](https://github.com/omnilib/aiosqlite)).

## Демонстрация

https://github.com/user-attachments/assets/a5d33b61-c38d-47d5-9d49-833adadd97ee

Видео (2,5 минуты): каталог и корзина, оформление заказа с доставкой, оплата тестовой картой,
смена статусов менеджером, удаление персональных данных.

## Возможности

**Для клиента**
- главное меню: Каталог, Корзина, Мои заказы, О нас;
- каталог: категории → товары → карточка товара с кнопками ➖ / ➕;
- корзина: список, сумма, изменение количества, очистка;
- корзина хранится в базе и не пропадает после перезапуска бота;
- оформление заказа по шагам: имя → телефон (можно кнопкой «Поделиться контактом») →
  самовывоз или доставка → адрес → комментарий → сводка и подтверждение;
  отменить можно на любом шаге кнопкой «❌ Отменить» или командой `/cancel`;
- при повторном заказе бот предлагает имя, телефон и адрес из прошлого заказа;
- оплата картой прямо в Telegram, по СБП или при получении — см. разделы
  [«Онлайн-оплата»](#онлайн-оплата-юkassa) и [«Оплата по СБП»](#оплата-по-сбп);
- после заказа — номер заказа; раздел «Мои заказы» со статусами, составом и оплатой;
- уведомления о смене статуса: готовится, готов (с адресом самовывоза или «едет курьер»),
  выполнен, отменён.

**Для менеджера** (Telegram ID указан в `ADMIN_IDS`)
- уведомление о каждом новом заказе со всеми данными, ссылкой на клиента и кнопками статусов:
  🆕 новый → 👩‍🍳 готовится → ✅ готов → 📦 выполнен, или ❌ отменён (с подтверждением);
- если менеджеров несколько, статус обновляется в уведомлениях у всех;
  устаревшая кнопка не сработает, а покажет актуальный статус;
- `/admin` — панель менеджера:
  - 📋 активные заказы (самые ранние сверху) с карточкой каждого заказа;
  - 🥐 наличие товаров: включить/выключить товар одним нажатием — снятые с продажи
    товары пропадают из каталога и не попадают в заказ;
  - 📊 статистика: заказы и выручка за сегодня, 7 дней и всё время, средний чек,
    сколько заказов в работе, топ-5 товаров.

Для обычного клиента команды `/admin` не существует — бот отвечает «Не понял вас».

**Персональные данные (152-ФЗ)**
- перед первым заказом — отдельный шаг согласия на обработку данных со ссылкой на политику
  и кнопками «Согласен» / «Отказаться»; без согласия заказ не оформить, каталог работает;
- согласие сохраняется в базе (Telegram ID, дата и время, версия текста) и больше
  не спрашивается — пока не поменяется версия текста;
- `/privacy` — какие данные о клиенте хранятся и кнопка «Отозвать согласие и удалить данные»:
  - если есть незавершённые заказы, удаление ждёт их выполнения или отмены — бот так и пишет;
  - имя, телефон, адрес и комментарии в заказах обезличиваются, суммы и состав остаются
    для статистики; уведомления о заказах у менеджеров тоже обновляются;
  - режим в `.env`: обезличивать сразу (`auto`) или отправлять запрос менеджеру (`manager`);
- журнал всех событий с данными (согласие, отзыв, удаление) — в `/admin` →
  «🔐 Персональные данные» → «📥 Журнал (CSV)»;
- шаблон политики обработки данных — [PRIVACY.md](PRIVACY.md).

## Запуск (пошагово для новичка)

### 1. Установите Python

Скачайте Python 3.11 или новее с [python.org](https://www.python.org/downloads/).
На Windows при установке **поставьте галочку «Add Python to PATH»**.

Проверка — в терминале должно появиться `Python 3.x.x`:

```bash
python --version
```

### 2. Создайте бота и узнайте свой ID

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, придумайте имя и username.
   BotFather пришлёт **токен** вида `1234567890:AAAA...`. Никому его не показывайте.
2. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) — это число.
   Он нужен, чтобы бот считал вас менеджером.

### 3. Скачайте проект и откройте терминал в его папке

На Windows: откройте папку в Проводнике, кликните в адресную строку,
введите `cmd` и нажмите Enter.

### 4. Создайте виртуальное окружение и установите библиотеки

Виртуальное окружение — это отдельная «коробка» с библиотеками только для этого проекта.

```bash
python -m venv .venv
```

Активируйте его. Windows:

```bash
.venv\Scripts\activate
```

macOS / Linux:

```bash
source .venv/bin/activate
```

В начале строки терминала появится `(.venv)`. Теперь установите библиотеки:

```bash
pip install -r requirements.txt
```

### 5. Настройте `.env`

Скопируйте файл `.env.example` под именем `.env` и впишите свои значения:

```env
BOT_TOKEN=1234567890:AAAA-ваш-токен
ADMIN_IDS=111111111
```

Несколько менеджеров — через запятую: `ADMIN_IDS=111111111,222222222`.

> Каждый менеджер должен **хотя бы раз нажать Start** в боте: Telegram не разрешает
> ботам писать первыми, и без этого уведомления о заказах до менеджера не дойдут.
> После изменения `.env` перезапустите бота.

Настройки персональных данных (необязательно, можно оставить как в `.env.example`):

```env
PRIVACY_POLICY_URL=https://ссылка-на-вашу-политику
PRIVACY_DELETION_MODE=auto
```

`PRIVACY_DELETION_MODE`: `auto` — данные обезличиваются сразу по запросу клиента,
`manager` — запрос приходит менеджерам с кнопками «Обезличить» / «Отклонить».

## Онлайн-оплата (ЮKassa)

Работает через встроенные платежи Telegram (Telegram Payments). Карту клиент вводит
в форме Telegram — бот данные карты не видит и не хранит.

**Как устроено:** клиент выбирает «💳 Оплатить онлайн» → бот присылает счёт →
перед списанием бот проверяет, что заказ не оплачен, товары в наличии и сумма та же →
после оплаты заказ получает отметку «✅ оплачен онлайн» и только тогда уходит менеджеру.
Пока заказ не оплачен, менеджер его не видит, а в «Моих заказах» у клиента есть кнопки
«💳 Оплатить» и «❌ Отменить заказ» (товары вернутся в корзину).

Если `PAYMENT_TOKEN` не задан, шага выбора оплаты нет — все заказы оплачиваются при получении.

### Как получить тестовый токен

1. Откройте [@BotFather](https://t.me/BotFather) → `/mybots` → выберите своего бота → **Payments**.
2. Выберите **ЮKassa** и вариант для теста (**Connect ЮKassa: Test**). Следуйте подсказкам —
   ЮKassa подключит тестовый магазин. Названия кнопок в BotFather могут немного отличаться.
3. BotFather покажет токен вида `381764678:TEST:12345`. Вставьте его в `.env`:

   ```env
   PAYMENT_TOKEN=381764678:TEST:12345
   ```

4. Перезапустите бота. В терминале появится `Онлайн-оплата включена: ТЕСТОВЫЙ режим ЮKassa`.

В тестовом режиме деньги не списываются, настоящие карты не принимаются.

### Тестовые карты

Из [документации ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
**Срок действия** — любая дата в будущем, **CVC** и код 3-D Secure — любые цифры.

| Карта | Что произойдёт |
|---|---|
| `5555 5555 5555 4444` | Успешная оплата (Mastercard) |
| `4111 1111 1111 1111` | Успешная оплата (Visa) |
| `2202 4743 0132 2987` | Успешная оплата (Мир) |
| `5555 5555 5555 4477` | Успешная оплата с вводом кода 3-D Secure (Mastercard) |
| `5555 5555 5555 4600` | Отказ: недостаточно средств |
| `5555 5555 5555 4527` | Отказ банка |

Если при подключении BotFather или ЮKassa показали вам другие тестовые данные — используйте их.

### Что проверить

1. Корзина от 100 ₽ → «Оформить заказ» → на шаге оплаты «💳 Картой в Telegram» → подтвердить.
2. Оплатить счёт успешной картой: должно прийти «✅ Оплата прошла!», менеджеру —
   уведомление с «✅ оплачен онлайн».
3. Попробовать карту с отказом — заказ остаётся «💳 Ждёт оплаты».
4. «📦 Мои заказы» → неоплаченный заказ → «❌ Отменить заказ»: товары вернутся в корзину.
5. В `/admin` снять товар с продажи и попробовать оплатить заказ с ним — оплата не пройдёт.

### Ограничения

- **Минимальная сумма.** Telegram не принимает платежи меньше ~1 $ (в рублях порог меняется
  вместе с курсом, сейчас около 90 ₽). Поэтому онлайн-оплату бот предлагает от 100 ₽ —
  настройка `MIN_ONLINE_PAYMENT` в `config.py`.
- **Возврат денег** бот сделать не может: если менеджер отменяет оплаченный заказ, бот
  напоминает вернуть деньги в личном кабинете ЮKassa и показывает номер платежа.
- **Повторная оплата** одного заказа заблокирована проверкой перед списанием. Если платёж
  всё-таки пришёл дважды (крайне редкий случай), второй не засчитывается, клиент и менеджер
  получают сообщение, а платёж сохраняется в таблице `payments` для возврата.

### Перед приёмом настоящих платежей

- Подключите в BotFather боевой (не тестовый) магазин ЮKassa и замените `PAYMENT_TOKEN`.
- Узнайте у ЮKassa, нужно ли передавать данные для чеков по 54-ФЗ: если да, в счёт
  нужно добавить `provider_data` с чеком — сейчас бот этого не делает.

## Оплата по СБП

Во встроенном счёте Telegram через ЮKassa доступны карты, ЮMoney и SberPay, а **СБП нет**.
Поэтому для СБП бот работает с ЮKassa напрямую через её API:

1. Клиент выбирает «⚡ По СБП» → бот создаёт платёж в ЮKassa и присылает кнопку
   «⚡ Оплатить через СБП». На телефоне откроется список банков, на компьютере — QR-код.
2. Клиент подтверждает оплату в приложении своего банка.
3. Бот раз в 5 секунд спрашивает у ЮKassa статус платежа (так проще, чем принимать
   уведомления от ЮKassa — для них нужен сервер с публичным адресом).
4. Оплачено → заказ уходит менеджеру с отметкой «⚡ ✅ оплачен по СБП».
   Не оплачен за 1 час или банк отказал → бот пишет клиенту, заказ остаётся «Ждёт оплаты»,
   его можно оплатить заново или отменить в «📦 Мои заказы».

Способы оплаты не зависят друг от друга: можно включить только карту, только СБП или оба.

### Как включить

1. Зарегистрируйтесь в [ЮKassa](https://yookassa.ru) и создайте **тестовый магазин**
   (подробно — в разделе про онлайн-оплату выше).
2. В личном кабинете тестового магазина откройте **Интеграция → Ключи API**: там ID магазина
   (shopId) и секретный ключ. Ключ тестового магазина начинается с `test_`.
3. Впишите их в `.env` и перезапустите бота:

   ```env
   YOOKASSA_SHOP_ID=123456
   YOOKASSA_SECRET_KEY=test_...
   ```

   В терминале появится `Оплата по СБП включена: ТЕСТОВЫЙ магазин ЮKassa`.

Секретный ключ — такой же секрет, как токен бота: только в `.env`, никому не отправляйте.

### Тестовый режим

[Тестовый магазин ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing)
поддерживает только карты и ЮMoney — СБП в нём проверить нельзя. Поэтому с ключом `test_…`
бот создаёт платёж тем же путём, но вместо СБП страница ЮKassa предложит оплатить
**тестовой картой** (таблица карт — выше). Так проверяется вся цепочка: ссылка → оплата →
бот сам замечает оплату → заказ уходит менеджеру. С боевым ключом `live_…` бот создаёт
настоящий платёж по СБП — для этого СБП должен быть подключён в магазине ЮKassa.

### Ограничения

- **Возврат денег** — вручную в личном кабинете ЮKassa (бот показывает номер платежа).
- Если клиент отменил заказ, но успел оплатить по старой ссылке, оплата не засчитывается:
  клиент и менеджер получают сообщение, платёж сохраняется в таблице `payments` для возврата.

### Перед запуском для настоящих клиентов

1. Заполните шаблон [PRIVACY.md](PRIVACY.md): все места с пометкой `[ЗАПОЛНИТЬ: …]`.
   В начале файла — памятка, что ещё проверить (её бот клиентам не показывает).
2. Впишите данные оператора в `texts.py` → `OPERATOR_NAME` (они видны в тексте согласия).
3. Опубликуйте политику и укажите ссылку в `PRIVACY_POLICY_URL`. Пока ссылки нет,
   бот присылает клиенту файл политики.
4. Покажите тексты юристу. Это шаблон, а не юридическая консультация.

### 6. Запустите бота

```bash
python bot.py
```

В терминале появится `Бот запущен`. Откройте своего бота в Telegram и нажмите **Start**.
Остановить бота — `Ctrl+C` в терминале.

При первом запуске создаётся файл `bakery.db` с демо-каталогом (хлеб, выпечка,
десерты, напитки). Чтобы начать «с чистого листа», остановите бота и удалите `bakery.db`.

## Частые проблемы

| Ошибка | Что делать |
|---|---|
| `Не задан BOT_TOKEN` | Нет файла `.env` или в нём пустой `BOT_TOKEN`. |
| `Unauthorized` / `Not Found` при старте | Токен неверный — скопируйте его заново у @BotFather. |
| `TelegramConflictError` | Бот уже запущен в другом окне или на другом компьютере. Оставьте один. |
| `ModuleNotFoundError: No module named 'aiogram'` | Не активировано окружение `.venv` (шаг 4). |
| Менеджеру не приходят заказы, в логе `Не удалось уведомить менеджера` | Менеджер не нажимал Start в боте или его ID в `ADMIN_IDS` указан с ошибкой. |
| Нет кнопки «💳 Картой в Telegram» | Не задан `PAYMENT_TOKEN` (или бот не перезапущен), либо заказ меньше 100 ₽. |
| Нет кнопки «⚡ По СБП» | Не заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, или бот не перезапущен. |
| Оплатил по СБП, а бот молчит | Подождите до 10 секунд. Если долго — в терминале будет строка `Не удалось узнать статус платежа` с причиной. |
| `/admin` отвечает «Не понял вас» | Ваш ID не указан в `ADMIN_IDS` — или бот не перезапущен после правки `.env`. |

## Тесты

67 автоматических проверок: корзина и быстрые нажатия, оформление заказа, работа менеджера,
персональные данные, оплата картой и по СБП.

Тесты не трогают ваш `.env` и `bakery.db` и не ходят в интернет: у каждого теста своя
временная база, а Telegram и ЮKassa заменены имитациями. Настоящий токен бота для них не нужен.

Установить инструменты для тестов (один раз, в активированном `.venv`):

```bash
pip install -r requirements-dev.txt
```

Запустить все тесты:

```bash
pytest
```

В конце появится строка вида `67 passed` — значит, всё работает. Если что-то сломалось,
pytest покажет, какой тест упал и что именно не совпало.

| Файл | Что проверяет |
|---|---|
| `tests/test_cart.py` | ➕/➖, лимит 50 шт, 20 одновременных нажатий, быстрые нажатия при медленной сети |
| `tests/test_checkout.py` | шаги оформления, проверку имени и телефона, отмену, двойное «Подтвердить» |
| `tests/test_admin.py` | доступ только для менеджеров, статусы, одновременные нажатия менеджеров, наличие, статистику |
| `tests/test_privacy.py` | согласие, `/privacy`, отложенное удаление, режим «решает менеджер», журнал |
| `tests/test_payments.py` | счёт, проверку перед списанием, повторную оплату, отмену неоплаченного заказа |
| `tests/test_sbp.py` | ссылку на оплату, опрос статуса, отмену со стороны ЮKassa, ошибки API |
| `tests/test_utils.py` | телефоны, цены, склонение слов, стоимость доставки |
| `tests/conftest.py` | общая подготовка: имитация Telegram и ЮKassa, временная база |

**Как поменять товары?** Наличие переключается в `/admin` → «🥐 Наличие товаров».
Названия, цены и состав каталога — в `database/seed.py` (затем удалите `bakery.db`
и перезапустите бота; заказы при этом тоже удалятся).

**Как поменять тексты уведомлений клиенту?** В `texts.py`, словарь `STATUS_MESSAGES`.

**Как поменять текст согласия?** В `texts.py` → `CONSENT_TEXT`. После правки обязательно
поменяйте `CONSENT_VERSION`: бот заново спросит согласие у всех, а в базе будет видно,
кто на какую версию текста соглашался.

**Как поменять стоимость доставки?** В `config.py`: `DELIVERY_PRICE` и `FREE_DELIVERY_FROM`.

**Важно:** шаги оформления хранятся в памяти бота. Если перезапустить бота, пока клиент
оформляет заказ, ему нужно будет начать оформление заново (корзина при этом сохранится).
